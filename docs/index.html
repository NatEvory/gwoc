gwoc

Git Worktree Orchestration CLI

Manage bare-repo hubs with one worktree per branch: work on many branches in parallel, each in its own directory, with no stashing and no branch switching.

the hub

A hub is a directory holding a bare repo and one worktree per branch. Every branch is just a directory. cd is your branch switcher, and nothing you do in one branch disturbs another.

~/dev/my-app
my-app/
├── my-app.git      ← bare repo (central store)
├── main            ← primary worktree, default branch
├── feature-x       ← worktree for branch feature-x
└── hotfix-123      ← worktree for branch hotfix-123

gwoc creates and maintains this layout for you: clone once, then grow and prune branches as directories.

quickstart

sh
$ gwoc clone git@github.com:you/your-repo.git   # creates ./your-repo/
$ cd your-repo

$ gwoc new feature-x        # worktree + branch at ./feature-x
$ cd feature-x              # ...edit, commit...

$ cd ..
$ gwoc merge feature-x      # merge into the primary worktree's branch
$ gwoc rm feature-x --prune # remove worktree and branch

what's in the box

checkout
check out any local or remote branch into a worktree, upstream wired
sync
fetch once, fast-forward the primary, rebase every worktree
doctor
health checks for the hub, with interactive --fix repair
hooks
post-init / post-clone / post-create at user, hub, and worktree level
manage
interactive worktree manager for point-and-pick cleanup
completion
bash, zsh, and fish tab completion, slug-aware
rename
move a worktree directory and its branch together
status
branch, cleanliness, and drift for one or all worktrees

install

script (linux / macos)

sh
$ curl -fsSL https://raw.githubusercontent.com/NatEvory/gwoc/main/install.sh | sh

Detects your platform, verifies the checksum, installs to /usr/local/bin or ~/.local/bin. Pin with GWOC_VERSION=v0.15.0; redirect with GWOC_INSTALL=~/bin. Binaries are glibc-linked, so Alpine/musl isn't supported. Requires git ≥ 2.35.

manual

Grab a binary from the latest release (linux/macos, x64/arm64, plus a windows build that is currently untested) and put it on your PATH. Self-contained: no runtime required.
